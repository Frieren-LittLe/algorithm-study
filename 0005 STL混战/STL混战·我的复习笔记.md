> 这份不是题解，也不是什么「STL 手册」。
> 就是把这 17 道题重新翻一遍，把当时查头文件查了半天的地方、后来才想明白的地方，用大白话记下来。
> 代码都取自 `0005 STL混战/`，是我自己写过的那些写法，可以打开对着看。
>
> 怎么用：哪个容器忘了怎么声明、忘了 `front` 还是 `top`，回来翻对应那一章的开头；

## 〇、先说三件最要紧的

回头翻这 17 道题，STL 用得再多，翻车翻得最多的还是这几条：

1. **`size` 是个函数，要带括号 `size()`。** 0002 我写成 `cout << q.size << endl;`，漏了括号——这在 C++ 里取的是函数地址，`cout` 会把它当成 `bool` 打印出 `1`，而且**编译不报错**。这种 bug 样例都测不出来，最阴。
2. **栈用 `top()`、队列用 `front()`，别串台。** 栈只有一头能碰（栈顶），所以叫 `top`；队列两头都有，进在尾、出在头，看队首叫 `front`。0002 的注释里我就把队首写成了「栈顶」，纯属嘴瓢，代码里是对的。
3. **空容器 `pop()` 是未定义行为，先判空。** 0001、0002、0013 都专门写了 `if (!empty())` 才 `pop`。别信「我数据保证非空」，多写一行 `empty()` 不亏。

再补一句选容器的心法，这是这 17 题真正想练的东西：

| 我想要什么 | 就用什么 |
|---|---|
| 后进先出、只在末尾进出 | `stack` |
| 先进先出、队尾进队头出 | `queue` |
| 随时取当前最小/最大 | `priority_queue`（堆） |
| 自动去重 + 自动排序 | `set` |
| 一个键对应一个值、按 key 找 | `map` |
| 只是存一串数、要排序 | `vector` + `sort` |

> **要记得**：容器选对了，代码十来行；选错了，自己模拟半天还容易错。动笔前先花十秒想「这题要的是哪种进出方式」。

## 一、栈 stack（0001、0005、0012、0013）

【栈】就一个特点：**后进先出**（LIFO）。像弹匣，最后压进去的那颗最先打出来。只能从一头（栈顶）放、从同一头取。

声明：`stack<类型> 名;`。五个动作：`push(x)` 压栈、`pop()` 弹栈、`top()` 看栈顶、`empty()` 判空、`size()` 数个数。

| 题号 | 题目 | 我记的一句 |
|---|---|---|
| 0001 | B3614 【模板】栈 | `push/pop/query/size` 四个操作照着敲，空栈 `pop` 输出 Empty、`query` 输出 Anguei |
| 0005 | P1449 后缀表达式 | 遇数字累加、遇 `.` 入栈、遇运算符弹两个算；**先弹的是右操作数** |
| 0012 | P1981 表达式求值 | 只有 `+` 和 `*`：`*` 立刻和栈顶乘掉，`+` 先入栈，最后统一累加 |
| 0013 | CF821C Okabe and Boxes | 重排一次=把整栈从大到小排好；已整理好的栈和空栈等价，直接清空 |

0005 的「先弹谁」是栈题最经典的一个坑，我当时在注释里特意标了：

```cpp
long long b = st.top(); st.pop();   // 先弹出的是靠后出现的 b
long long a = st.top(); st.pop();   // 后弹出的是靠前的 a
if (c == '-') st.push(a - b);       // 减法除法必须 a-b、a/b，反了就错
```

加减乘反过来没事，`-` 和 `/` 反了直接错。记住：**后弹出来的才是左边的数**。

0012 值得单独说。题目只含 `+` 和 `*`，而 `*` 优先级高，所以我们可以**边读边把乘法算掉**：

```cpp
while (cin >> op >> num) {
    num %= MOD;
    if (op == '+') st.push(num);
    if (op == '*') {                       // 乘法优先：立刻和栈顶算完
        int cur = st.top(); st.pop();
        st.push((cur * num) % MOD);
    }
}
// 栈里现在只剩一堆「该相加的项」，逐个累加
while (!st.empty()) ans = (ans + st.top()) % MOD, st.pop();
```

> **要记得**：
> - 0001 用了 `unsigned long long`，题目数据能到 `2^64`；往里塞负数会按模 `2^64` 回绕成一个巨大正数，而且 `cin` 不报错，别拿它存负数。
> - 0012 最后累加那行我写的是 `ans = (ans + st.top() & MOD)`——`&` 是按位与、优先级又比 `+` 低，这里其实是 `(ans + st.top()) & MOD`，不是取模 10000。**正确写法是 `% MOD`**（改动很小，但没动原文件，先记着）。
> - 0013 那题的「重排」不是交换一次，是花一次代价把整栈重排好。想通「排好之后所有 remove 都能顺序弹出」之后，代码里直接用 `empty()` 代替模拟重排，这是我最满意的一个建模。

## 二、队列 queue（0002、0011）

【队列】也是只能一头进一头出，但跟栈反着：**先进先出**（FIFO）。队尾进（`push`），队头出（`pop`），看队头用 `front()`。像排队买饭，先来的先走。

| 题号 | 题目 | 我记的一句 |
|---|---|---|
| 0002 | B3616 【模板】队列 | `push/pop/front/size` 四个操作；空队列 `pop`/`front` 报固定错误串 |
| 0011 | P1996 约瑟夫问题 | 报数时把前 `m-1` 个搬到队尾，第 `m` 个输出并弹掉 |

0011 是队列最漂亮的用法——用队列模拟「首尾相接的圆圈」。报数到 `m` 的人出圈，其余人按原顺序接着排：

```cpp
while (!q.empty()) {
    for (int i = 1; i < m; i++) {   // 前 m-1 个：挪到队尾，等于绕一圈
        q.push(q.front()); q.pop();
    }
    cout << q.front() << " ";       // 第 m 个：输出并出圈
    q.pop();
}
```

不用数组、不用取模下标，人与人之间的先后顺序全交给队列维护。

> **要记得**：
> - 0002 那行 `cout << q.size << endl;` 少了括号，输出永远是 `1`（见第〇章第 1 条）——这是我在这个题单里最该改的一处。
> - 队列没有 `top()`，只有 `front()`（队头）和 `back()`（队尾）。写顺手了容易跟栈混。

## 三、堆 priority_queue（0003、0006）

【堆】严格说是「优先队列」：你只管往里塞，它永远把最大（或最小）的那个顶在最上面给你。取最值 `O(1)`，插入/删除 `O(log n)`，但**内部不保证全有序，也不能遍历**。

默认是大根堆。要小根堆得写全三个参数：

```cpp
priority_queue<int> pq;                                   // 默认：大根堆，top 是最大
priority_queue<int, vector<int>, greater<int>> pq;        // 小根堆，top 是最小
```

`greater<int>` 在 `<functional>` 里（有些编译器 `iostream` 顺带引进来了，但不保证，老老实实 include）。

| 题号 | 题目 | 我记的一句 |
|---|---|---|
| 0003 | P3378 【模板】堆 | 小根堆三板斧：`push` 插入、`top` 看最小、`pop` 弹最小 |
| 0006 | P1090 合并果子 | 每次挑最小的两堆合并，把和塞回去，累加消耗 |

0006 是贪心 + 堆的教科书题。为什么要每次合并最小的两堆？因为**越早合并的果子，在后面会被反复加进去**：先合大的，它会被多算好几次，总和就大了。

```cpp
while (pq.size() > 1) {
    int a = pq.top(); pq.pop();     // 最小的
    int b = pq.top(); pq.pop();     // 第二小的
    int c = a + b;
    sum += c;                       // 这次消耗的体力
    pq.push(c);                     // 合完的堆再丢回去
}
```

> **要记得**：
> - 答案是消耗体力的累加，会超过 `int`，这题 `sum` 我用的 `int` ——n 大、果子重时会溢出，稳妥点写 `long long`。
> - 堆不能遍历、不能按下标取，要「全部拿出来」就得反复 `top`+`pop`。

## 四、集合 set（0004、0016、0017）

【set】两个关键词：**自动去重** + **自动排序**（默认升序）。往里 `insert` 一堆乱序重复的数，它自己就帮你排好、去重了。

常用动作：`insert(x)` 插入、`count(x)` 判存在（返回 0 或 1）、`find(x)` 找（返回迭代器，找不到是 `end()`）、`erase(x)` 删、`size()`、`lower_bound(x)`（第一个 ≥x 的位置）。

| 题号 | 题目 | 我记的一句 |
|---|---|---|
| 0004 | P3370 字符串哈希 | 每个串算成 ull 哈希，塞进 `set`，最后 `size()` 就是不同串个数 |
| 0016 | P5250 木材仓库 | `lower_bound` 找到第一个 ≥len 的，和它前一个比谁更近 |
| 0017 | P1978 集合 | 排序 + set：是 k 倍数的数，若 `a[i]/k` 已在集合里就跳过 |

0016 是 set 的一个高频套路——**找最接近目标值的元素**。因为 set 有序，`lower_bound(len)` 会给你第一个 ≥len 的，那答案只可能在它（偏大）和它前一个（偏小）之间：

```cpp
auto it = s.lower_bound(len);       // 第一个 >= len 的
if (it == s.begin())      cout << *it;          // 没有更小的，只能取它
else if (it == s.end())   cout << *prev(it);    // 没有更大的，取最后一个
else {
    auto pre = prev(it);
    if (len - *pre <= *it - len) cout << *pre;   // 一样近时取短的
    else cout << *it;
}
```

0017 则是「set 当去重工具 + 贪心」。排完序从小到大扫，靠 `find(a[i]/k)` 判断这个数的「一半」在不在，在就跳过。

> **要记得**：
> - 0016 我这份代码里变量声明的是 `set<int> t;`，下面却全写成 `s.count(...)`、`s.insert(...)`——`s` 根本没定义，这是**编译不过**的笔误，得把声明改成 `s`（或把用的地方全改成 `t`）。另外 `it == s.begin()` 那个分支里 `s.erase(pre)` 的 `pre` 也没定义，应该是 `erase(it)`。没动原文件，先记着。
> - `lower_bound` 返回的是**迭代器**不是值，取值要 `*`；`prev(it)` / `next(it)` 在 `<iterator>` 里。
> - `set` 只去重、不改值。想改某个元素得先 `erase` 再 `insert`。

## 五、map（0014、0015）

【map】是键值对容器：一个 key 对应一个 value，按 key 自动排序，用 `key` 找 value 很快（`O(log n)`）。可以把数组下标那种「整数当索引」升级成「任何类型当索引」。

| 题号 | 题目 | 我记的一句 |
|---|---|---|
| 0014 | P1918 保龄球 | **键值反转**：用「打倒几个瓶子」当 key、「位置」当 value |
| 0015 | P5266 学籍管理 | `mp[s]=分` 改、`find` 查、`erase` 删、`size` 数 |

0014 是这 17 题里思路最值钱的一道——**键值反转**。题面问的是「打倒 m 个瓶子的位置在哪」，正常想法是用位置当下标存瓶子数，但位置对应瓶子数最大到 `1e9`，开数组要 3.8G，直接 MLE。反过来存：

```cpp
map<int, int> mp;
for (int i = 1; i <= n; i++) {
    int x; cin >> x;
    mp[x] = i;                 // key=瓶子数, value=位置
}
// 问 m：cout << mp[m]，一句话
```

map 是「用哪个 key 才开哪个格子」，只开 `n=1e5` 个，约 390KB，轻松过。这就是它的价值：**key 很大很稀疏、但实际用到的没几个**的时候，别用数组硬开。

0015 就是 map 增删改查的模板题，记住 `find(s) == end()` 表示不存在即可。

> **要记得**：
> - `find` 返回迭代器，要用 `auto` 接，别用 `int`。判存在写 `mp.find(s) != mp.end()`。
> - `map` 用 `[]` 访问不存在的键会**自动建一个默认值**（value 是 0），不想误建就先 `find` 判断。
> - 键值反转的前提：题目保证 key 不重复（0014 保证各位置瓶子数不同）。会重复就不能简单反转。

## 六、vector + sort（0007、0008、0009、0010、0017）

剩下几道没用花哨容器，就是 `vector` 存数 + `sort` 排序，考的是「排完序之后再处理」。

| 题号 | 题目 | 我记的一句 |
|---|---|---|
| 0007 | CF1744A Number Replacement | n≤50，双重循环：同一个数字出现的位置，字母必须都一样 |
| 0008 | P1097 统计数字 | 排序后相同的数挨在一起，用 `cnt` 记起点，数连续段输出 |
| 0009 | CF1742B Increasing | 排序后若有相邻相等 → 排不成严格递增，输出 NO |
| 0010 | CF1850D Balanced Round | 排序后找最长的一段，段内相邻差 ≤k；答案 = n − 最长段 |

0007 是这批里唯一「暴力就行」的：题目允许不同数字变成同一个字母，只禁止同一个数字变成不同字母。所以检查「同一个数字对应的字母是否唯一」即可，n≤50 两重循环：

```cpp
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        if (a[i] == a[j] && s[i] != s[j]) { cout << "NO\n"; return; }
cout << "YES\n";
```

0009 和 0010 都是「排序之后看相邻」的路子，一个查相等、一个查差值分段。

> **要记得**：
> - `sort` 默认升序，要降序传 `greater<int>()`（第三参数，如 `sort(a, a+n, greater<int>())`）。
> - 0008 最后一组数是在循环外单独输出的（`cout << a[cnt] << " " << n - cnt`），别漏，否则最后一个数统计不到。
> - 0010 数组开 `n+1`、从下标 1 存，这样 `a[i]-a[i-1]` 第一项天然是 `a[1]-a[0]=a[1]`，省了特判。这叫「哨兵」，挺好用。

## 七、回头看，其实就三条线

把 17 题合起来看，来来回回就这几件事：

1. **先选对容器，代码自然就短。** 要后进先出用 stack、先进先出用 queue、随时取最值用堆、要去重排序用 set、要键值查用 map。选错了就得自己模拟，又长又容易错。
2. **「排完序再处理」出现得特别多。** 0008、0009、0010、0017 全是排序之后看相邻/分段。卡住的时候先问自己一句：**排个序会不会变简单？**
3. **空容器、函数括号、迭代器——STL 的三个高频坑。** `pop` 前判空、`size()`/`front()` 带括号、`find`/`lower_bound` 返回的是迭代器。这三样错一个，样例经常还过得去，交上去才挂。

## 八、要记得（提交前再过一遍）

1. `size`、`front`、`top` 都是函数，带括号；写成 `q.size` 会静默打印 `1`（0002）。
2. 栈用 `top()`、队列用 `front()`；空容器 `pop` 前先 `empty()`。
3. 后缀表达式（0005）、减法除法：`-` 和 `/` 必须用「后弹出的 a」在前。
4. 小根堆写全：`priority_queue<int, vector<int>, greater<int>>`；累加答案用 `long long`（0006）。
5. `set` 有序才能 `lower_bound`；返回值是迭代器，取值加 `*`，前一个是 `prev(it)`。
6. `map` 的 `[]` 会误建键；判存在先 `find`。键值反转要保证 key 不重复（0014）。
7. `sort` 后处理：`unique` 只去相邻重复、0008 最后一组在循环外输出、0010 用 `a[0]=0` 当哨兵。

> 顺手记几个我自己代码里还能改的地方（**都没动原文件**，先记着，回头修）：
> - **0002**：`q.size` → `q.size()`。
> - **0012**：`ans = (ans + st.top() & MOD)` → `ans = (ans + st.top()) % MOD`。
> - **0016**：变量声明 `set<int> t;` 但下面全用了 `s`，改成 `s`；`it==begin()` 分支里 `s.erase(pre)` 的 `pre` 未定义，应为 `erase(it)`。
> - 这几处有的编译不过、有的样例恰好测不出来，都是「看着对、跑起来错」的典型，_mark 一下。

## 十、接下来

STL 混战停在「容器基本用法 + 排序贪心」这一层，往下的路挺清楚的：

1. **容器的进阶搭配**：`set` 换 `unordered_set`（要快不要序）、`map` 换 `unordered_map`；`deque` 两头都能进出的队列。
2. **堆的高级玩法**：对顶堆（动态中位数，一个顶堆 13 的思路更彻底）、堆优化 Dijkstra。
3. **二分和 set/map 结合**：`lower_bound`/`upper_bound` 本身就是二分，配合有序容器能解决一大类「找位置」的题。
4. **回到算法主线**：这 17 题的排序贪心部分（0008/0009/0010）正好接上 46 题笔记里的【排序】【贪心】两章。

复习的话，按容器一章一章回做就行，每章挑 1 题**关掉笔记自己重写一遍**；隔一周、隔一个月再来一轮。能一次写对、括号都不漏，才算真的会了。
