## 〇、这套题集是"55 个真实案例"

做这 55 题时请记住三件事，它们来自对全部题解的通读：

1. **注释就是最好的老师**。这 55 份带注释题解里，作者把"为什么这么写"讲得很细（比如 0023 为什么先用 `int t = i` 保护循环变量、0020 为什么时间要统一换算成分钟）。做题前先看题目、卡住了再看注释，比直接抄代码有用得多。
2. **注释也可能有笔误，以代码为准**。通读发现注释层笔误不少（把 `true` 写成 `ture`、把"下标"写成"底标"、把 `==` 讲成 `=` 等），个别题（0012、0016、0045 等）甚至整份没注释。代码本身几乎都能编译，但**读注释时要留个心眼：注释是参考，代码是标准**。
3. **同一种坑会反复出现**。比如"整数除整数=整除"出现在 0007、0010、0014、0049，"漏了 `fixed` 导致小数位数错"出现在 0007、0010、0011、0013、0046——第一次踩了，后面就别再踩。

## 一、为什么要刷这 55 题

它是一张**循序渐进的技能地图**，不是 55 道孤立的题。它按"先基础、再分支、再循环、再数组、再函数递归"的顺序排，**难度一路爬坡**。你能明显感觉到：

- 前面（001~020）几乎"送分"，是用来**熟悉输入输出、建立信心**的；
- 中间（021~040）开始要**动点脑子**，用到循环、数组、字符串；
- 后面（041~055）是**真正的进阶**，结构体、函数、递归，做完你就有底气说"我入门了"。

**重要心态**：刷题的**目的不是 AC 的数量，而是"这个知识我真正会用了"**。一道题卡 30 分钟以上可以先跳过或看题解，但**必须弄懂再看下一题**，切忌"抄完交掉就当刷过"。

## 二、解题方式的要求（新手必须严格遵守的规范）

这些是 OJ 刷题的**硬性规则**，学校/团队也据此检查你的代码。每一条都是常见的丢分点。

### 1. 只输出题目要求的，其它一个字都不要多
OJ 是**逐字符比对**。你的程序**只能输出题目要求的内容**，绝不能输出任何提示文字：

```cpp
// ❌ 错：多输出了提示
cout << "答案是：" << a + b << endl;

// ✓ 对：只输出结果
cout << a + b << endl;
```

`"答案是"`、为了调试加的 `print`、英文提示……一旦写了就 WA。

### 2. 按题目要求的格式精确输出
- 题目说**输出几行**，就写几个输出、每行结尾 `endl`（或 `\n`）；
- 题目说**空格分隔**，就在数之间加 `" "`；
- 题目说**保留 k 位小数**，就用 `fixed << setprecision(k)` 或者 `printf("%.kf\n",x)`；
- 题目给的是**固定单词**（如 `Normal`），就**一字不差**照抄，注意大小写。

（详见《读题指南》的高频翻车点清单。）

### 3. 头文件、命名空间、main 函数是基本盘
```cpp
#include <iostream>          // 输入输出
#include <cstdio>            // 用 scanf、printf 读写时
#include <iomanip>           // setprecision 等格式化（用时才加）
#include <cmath>             // sqrt、pow 等数学函数（用时才加）
#include <string>            // 用到 string 时
#include <algorithm>         // reverse、sort 等算法（用时才加）
using namespace std;

int main() {
    // 你的代码
    return 0;
}
```
用到哪个库就引哪个头文件，别图省事一把梭 `#include <bits/stdc++.h>`（虽然很多 OJ 支持，但**养成按需引入的好习惯**）。

### 4. 变量命名要能看懂
用 `n`、`sum`、`maxVal`、`stu` 这种能看出含义的名字。你看题解的注释，正是靠"名字——含义"来理解的。

### 5. 养成写注释的习惯
关键步骤写一行注释，说明"**这里在干什么**"。这既是给队友看，也是给自己复习看（你现在每道题的带注释版本就是这么来的）。但**注释不要输出到屏幕**——注释只是代码里给人看的，OJ 不会读，也不会影响判题。

### 6. 会读题，再动手
拿到题**先按《读题指南》的三步法**把题意讲清楚，再写代码。**读题比写代码更花时间是正常的**。

### 7. 提交前自测，别一上来就交
自己造几组数据（大小边界、0、负数、`n=1`）在本地/IDE 里跑一遍，**样例通过 + 边界想清楚**再提交，减少无谓的 WA。AC 了也别立刻下一题，**回头看一眼复杂度在自己掌控内吗、有没有更优写法**。

## 四、建议的刷题节奏

| 阶段 | 建议节奏 |
| --- | --- |
| 001~015 顺序 | 每天 5~8 题冲刺，**快速建立手感**，别恋战 |
| 016~020 分支 | 放慢，**认真理解 `if/else` 和边界条件** |
| 021~035 循环/数组/字符串 | 核心，**宁可慢也要吃透**，多看注释版怎么遍历 |
| 036~040 二维数组 | **这部分是坎**，卡住正常，配合画图理解 |
| 041~045 结构体 | 熟悉 `struct` 写法即可，较轻松 |
| 046~055 函数/递归 | **最高难度**，递归必须作图/画栈理解，别死记 |

**通用铁律**：
1. **先看懂题，再写代码**（读题指南）。
2. **每个知识点务必自己敲一遍**，别只复制注释版。
3. **卡超过 30 分钟先跳**，回头弄懂；但**交了的题要能讲给别人听**。
4. **做完一阶段，回头看这一阶段的所有题能不能独立秒出**——能，才算过关。

## 五、常见新手问题（Q&A）

**Q：我总是 WA，怎么办？**
先自己查：读到的东西对吗？输出格式（行数/空格/小数/大小写）对吗？类型会不会溢出？边界（0、负数、n=1）测了吗？再不行，把样例输入**手算一遍**看理解对不对。都查过才看题解。

**Q：要不要看题解？**
可以看，但**先自己思考 30 分钟**。看题解时不是抄代码，而是**看懂"为什么这么想"**，然后合上书自己重写一遍。

**Q：代码对了但过不了样例，差在哪？**
99% 是**输出格式**：多了空格、少了 `endl`、小数位数不对、大小写不对、多输了提示文字。对照"解题方式要求"第 1、2 条逐条排。

**Q：这 55 题做完能干嘛？**
你已经具备**顺序/分支/循环/数组/字符串/结构体/函数递归**的完整基础，可以进算法题（枚举、贪心、搜索、排序、DP 入门）。

---

*最后一句：入门阶段比的不是谁聪明，是**谁更扎实、谁更有耐心**。把 55 题一道一道啃下来，你会亲眼看到自己的进步。*
